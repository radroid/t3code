What the codebase actually allows

Seven agents read the tree against merge-base 64bf01619. Three findings decided the design; three traps killed the designs that ignored them.

The findings

Finding 01 — the whole trigger
Idle detection is already subagent-aware, for free

thread.activity-appended bumps projection_threads.updated_at in both writers — the SQL pipeline and the in-memory projector. Background subagent task.* events are activity appends. So a plain now − shell.updatedAt > N test stays quiet through all 1,358 orphaned activities and fires exactly at the start of the dead air. It reads a SQL column, not a hot stream, so it is also the only candidate trigger that survives a server restart.

ProjectionPipeline.ts:794-808 · projector.ts:747-750
Finding 02 — zero server seams
A fork reactor can already restart a thread

engine.dispatch({type:"thread.turn.start", …}) from a fork-owned reactor registered in t3x/index.ts produces an ordinary user turn — byte-for-byte the path a keystroke takes. Auto-resume has done exactly this in production since #6. The three server.ts seam lines already exist; the loop adds none.

Finding 03 — the settings surface exists
There is already a Beta panel to hang this on

BetaSettingsPanel.tsx (upstream churn 3) is a working template with a Switch row and a numeric sub-row. Two lines mount a fork-owned section inside its existing container — risk 6, against risk 1044 for the main settings panel the fork already edits.

The traps

Trap 01 — would deadlock
Never gate on session.status

A background subagent's assistant message auto-opens a synthetic turn that pins session.status = "running", and nothing closes it but a later SDK result. On exactly the issue-38 threads, status can be stuck “running” forever — so reusing auto-resume's threadIsProgressing as a veto would never fire. Here “running” only lengthens the fuse: 15 minutes idle, 45 if a turn looks busy.

ClaudeAdapter.ts:2469-2489 · autoResume/guards.ts:107-111
Trap 02 — silently destructive
thread.turn.start clears snooze and the keep-active pin

The decider unsettles for settledOverride !== null — so it wipes an explicit “keep active” pin, not just a settle — and unsnoozes unconditionally. No opt-out. Loop Watch therefore refuses to dispatch on a snoozed thread, and re-issues thread.unsettle{reason:"user"} to restore the pin when one was there.

decider.ts:820-844 · contracts/orchestration.ts:594-601
Trap 03 — collision course
Upstream is building this, in the sidebar

Upstream #3164 “Automations & Triggers (for loops)” is 🚧 In Progress, landing in apps/web; #5123 asks for a thread.wake-if-idle command whose landing zone upstream has pre-announced in a contracts comment. So: no sidebar section, no command literal, no contracts edit, nothing named “automation” — and when #5123 lands, our nudge branch becomes a caller with no migration.

pingdotgg/t3code#3164 · #5123 · contracts/orchestration.ts
One more thing that decided the shape: T3 Code drives Claude through @anthropic-ai/claude-agent-sdk in streaming-input mode — not the interactive CLI harness. There is no self-scheduling tool inside a turn. The agent literally cannot re-invoke itself across a turn boundary, which is why your /loop attempt that night could never have worked. Any loop has to be driven server-side.

04

How Loop Watch works

One reactor under apps/server/src/coil/loop/, shaped exactly like the auto-resume one beside it. It watches one SQL column, and it is read-only on your filesystem.

01 · Arm
You flip two switches

The beta master toggle in Settings, and Loop watch on the thread you're walking away from. Nothing is ever supervised implicitly. Max 3 armed threads.

02 · Watch
Poll every 60s

Per armed thread: two single-row reads. idleMs = now − shell.updatedAt. Zero SQL when nothing is armed. Never getSnapshot().

03 · Gate
Fourteen guards

Snoozed, settled, needs-approval, needs-input, plan-ready, rate-limited, auto-resume pending — all skip without spending budget, and say so in the pill.

04 · Nudge
An ordinary user turn

Counter persisted before dispatch so a failing provider burns budget, not 480 retries. Then the keep-active pin is repaired, then a breadcrumb lands on the timeline.

05 · Stop
Four ways, all sticky

done (you wrote the sentinel) · spent (budget or 07:00) · stalled (two dead nudges) · handed-back (you typed). Only a human re-arms.

The stop signal is a file you can touch

When the work is done — or when it's blocked on you — the agent writes .t3x/loop-done with one line of reason. That's an ordinary Write call. It works identically under claude in a terminal, with no bespoke tool and no protocol.

The supervisor only ever stats that path — worktree first, then workspace root, newest mtime wins, honoured only if it's newer than the moment you armed. It never writes to your filesystem, which is what makes it safe to point at any repo. touch .t3x/loop-done stops a run from a terminal; rm keeps it going.

The check-in text is the feature

Restated in full every time, because a six-check-in overnight run will compact away anything taught once. Overridable per thread, or committed to .t3x/loop-prompt.md. 

[t3x loop watch — automated check-in 2 of 6]

This thread has produced no activity for 47
minutes. If you are still working, ignore this
message and carry on.

Otherwise: do NOT restart from the top and do NOT
redo finished work. First re-read your own progress
notes for this repo (.loop/state.json, logs/,
GOALS.md, iter-NNN.md — whatever this repo uses),
then continue from the next unfinished item.

When the work is finished, or when you are blocked
and need a human, write this exact file:

  /Users/you/repo/.t3x/loop-done

with one line saying why you stopped. That file is
the only way to end this loop early. Otherwise it
ends after 6 check-ins, or at 07:00, whichever
comes first.

I am the scheduler for this thread. Do not schedule
your own wake-ups.
That last line is not decoration. Your autonomous-build-loop skill has the agent scheduling its own wake-ups — which, inside T3 Code, silently do nothing. One sentence resolves two schedulers into one.

08

What this honestly does not solve

Written down now, so nobody discovers them at 4am.

  • A single silent tool call longer than 45 minutes reads as idle. The nudge is then absorbed as a steer into the live turn with no visible turn boundary, and you'd see a derailed agent with no obvious cause. On this repo that's not hypothetical — the full suite needs --concurrency-limit 2 and a raised hook timeout. Mitigated by the 45-minute default, per-thread overrides, and a check-in written to be harmless as an interjection. Not eliminated.
  • Without the sentinel, done is unreachable and every run ends spent. Your own loop protocol says outright that the loop never halts on a semantic event, so your agents are conditioned against declaring completion at all. That's why the absolute path is interpolated, why the contract is restated every check-in — and why spent is visually distinct rather than quietly green.
  • Phone delivery is not solved by Phase 2 alone. The service worker returns early whenever that device has a T3 window open, so a phone with a backgrounded, frozen tab suppresses its own push. Three of the four designs got this backwards. The in-page fallback is a partial answer and needs real on-device testing before anyone calls it working.
  • Two fork reactors now dispatch turns to the same thread, with no shared lock. The pending-resume guard plus durable rate-limit suppression closes both directions I can find, but a third producer would have nothing to compose against. A new Parallel-paths row in SEAMS.md is the only tripwire.
  • The trigger rests on incidental upstream bookkeeping. A full-row upsert per activity append is precisely the shape upstream optimises. The shipped contract test catches a semantic change — but only if it keeps running against real projection wiring rather than stubs. This fork has been bitten by a semantically-dead test once already.
  • Upstream #3164 may make this redundant. If automations ship with their own enablement and budget gates, Loop Watch becomes a parallel path that bypasses all of them with no conflict, no type error and no failing test. Retirement is rm -r apps/server/src/coil/loop apps/web/src/coil/Loop* plus reverting three lines, and the ledger row will carry that adopt-or-sunset criterion explicitly.
  • Cost is not metered in dollars. The budget is turns and wall-clock. total_cost_usd flows from the SDK but nothing in this repo has ever read it, and its per-turn vs per-session semantics are unverified — a ledger whose whole selling point is trust must not rest on a number nobody has checked.
